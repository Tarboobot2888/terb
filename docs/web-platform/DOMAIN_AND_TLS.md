# DOMAIN_AND_TLS — الدومين وإثبات الملكية والشهادة

> المبدأ: **لا يُوعَد بما لا تدعمه البيئة.** البوت لا يصدر شهادات ولا يعدّل
> نظاماً. الدومين لا يُعتمد قبل تحقّق DNS حقيقي. الرابط القانوني مصدره واحد.

## 1. مصدر الرابط الواحد

`config.website.publicBaseUrl` عبر `src/web/url-builder.js` **فقط**. لا
`info.website` ولا `socialLinks.website` (قناة واتساب) ولا ترويسة `Host`.

ترتيب `publicBaseUrl()`:
1. عنوان صريح من المالك في الإعداد (لكن إن حمل الدومين المُعدّ لزم تحقّقه).
2. دومين متحقَّق ⇒ `https://<domain>`.
3. `publicIp` يحدّده المالك ⇒ `http://<ip>:<port>` (يُعلَن غير مشفَّر).
4. وإلا `""` ⇒ لا رابط ولا زر.

## 2. ضبط الدومين والتحقق (من واتساب)

```
.موقع دومين bot.example.com      # يقبل بعد تحقق نحوي، ويولّد رمز إثبات
.موقع تحقق                        # dns.resolveTxt حقيقي
.موقع رابط                        # الرابط القانوني الحالي ومستوى أمانه
```

أو من لوحة المالك على الموقع (تبويب الموقع).

### خطوة التحقق

بعد `set-domain` أضف سجل DNS:

```
TXT   _terboo-verify.bot.example.com   <الرمز المعروض>
```

ثم `.موقع تحقق`. الخادم يستعلم `_terboo-verify.<domain>` فعلاً ويطابق الرمز.
**قبل النجاح:** `publicBaseUrl` لا يُبنى، وزر القائمة لا يظهر، والحالة
`domain-pending-verification`.

## 3. توجيه الدومين

`routingCheck()` يفحص A/AAAA/CNAME ويقارنها بـ`publicIp` المُعدّ (إن وُجد)
ليخبر المالك إن كان التوجيه صحيحاً — ويبقى **TXT** هو شرط الاعتماد، لا A.

## 4. TLS — ثلاثة أوضاع

| `tlsMode` | المعنى | متى |
|---|---|---|
| `proxy` (افتراضي) | TLS عند reverse proxy أمام الموقع | **الموصى به** — البوت لا يحمل شهادة |
| `direct` | الموقع يقدّم HTTPS من `tls.certPath`/`keyPath` | شهادة موجودة على القرص |
| `disabled` | HTTP صريح | تطوير محلي فقط — يُعلَن غير آمن |

### حالة الشهادة

`.موقع شهادة` أو تبويب TLS: تقرأ الشهادة المُعدّة (انتهاء · تطابق الاسم ·
صلاحيات المفتاح) بلا إعادة أي مفتاح أو محتوى. المفتاح الخاص **لا** يُقدَّم
كأصل ثابت ولا يُعاد في أي API، وتُحذّر إن كانت صلاحياته أوسع من 600.

### الإصدار والتجديد — خارج البوت

`.موقع شهادة اصدار` و`/owner/tls/issue` **يُرفضان بسبب صريح**:
```
NOT_AVAILABLE_IN_WEB: issuance is done by the reverse proxy or ACME client
outside the bot process.
```
السبب: عملية بوت غير privileged يجب ألا تعدّل جدار الحماية أو systemd أو
تشغّل سلسلة shell مبنية من دومين. الإصدار يتم عبر:

**Caddy (تلقائي):** يصدر ويجدّد تلقائياً بمجرد توجيه الدومين إليه.

**Let's Encrypt + Nginx:**
```bash
sudo certbot --nginx -d bot.example.com
# التجديد تلقائي عبر certbot.timer
```

بعد الإصدار: `publicBaseUrl: "https://bot.example.com"` و`.موقع تحقق`.

## 5. الرابط الاحتياطي عند غياب الدومين

`publicIp` يحدّده المالك ⇒ `http://<ip>:<port>`، **يُعلَن غير مشفَّر**
(`ready-insecure-http`) ولا يُسوَّق كـHTTPS. لا يُكتشف العنوان من ترويسة ولا
خدمة خارجية تلقائياً.

## 6. حالات الموقع

| الحالة | المعنى |
|---|---|
| `disabled` | `website.enabled = false` |
| `domain-pending-verification` | دومين مُعدّ لم يُتحقَّق منه |
| `tls-missing` | `tlsMode: direct` بلا ملفات شهادة |
| `no-public-address` | لا دومين متحقَّق ولا IP |
| `ready-insecure-http` | يعمل على HTTP غير مشفَّر |
| `ready` | جاهز ومشفَّر |

## 7. الأمان

- المفتاح الخاص خارج webroot، صلاحيات مقيّدة، لا يُعاد في API ولا يُقدَّم كأصل.
- فحص Host-header poisoning و DNS rebinding: الرابط من الإعداد لا من الطلب.
- خلف NAT/حاوية بلا صلاحية فتح 80/443: تُعرض خطوات الإعداد للمالك، ولا يُدّعى
  إصدار شهادة لم يحدث.
